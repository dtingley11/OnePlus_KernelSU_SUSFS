# Ace 6T / OnePlus 15R builds

This profile builds an Android 16 / Linux 6.12.38 common GKI kernel with
KernelSU-Next and SUSFS. It reuses WildKernels' matrix, archive source sync,
compiler detection, ccache, `make`, AnyKernel3 packaging, artifact upload, and
optional draft releases. Kernel sources are fetched during each run and never
committed here. Your separate `dtingley11/android_kernel_oneplus_sm8845` fork is
not changed or used as a substitute for the common kernel.

**Validation status:** the Ace 6T profile compiled and packaged successfully in
[Actions run 39335220516](https://github.com/dtingley11/OnePlus_KernelSU_SUSFS/actions/runs/39335220516).
The downloaded artifact passed checksum, ZIP integrity, ARM64 header and
configuration checks. The 15R profile has only local static/patch validation.
Neither profile has been boot-tested here; no firmware build is certified
compatible yet. See the investigation and validation notes below before installation.

## Put these changes in a workflow fork

1. Fork [WildKernels/OnePlus_KernelSU_SUSFS](https://github.com/WildKernels/OnePlus_KernelSU_SUSFS/fork).
   This is the small build repository, separate from the OnePlus kernel source.
2. Put the prepared commits on your fork's default branch. For this local
   checkout, the following commands preserve the original `origin` reference;
   substitute your workflow fork URL if you choose a different name:

   ```sh
   cd /home/dylantingley/OnePlus_KernelSU_SUSFS
   git remote add fork https://github.com/dtingley11/OnePlus_KernelSU_SUSFS.git
   git push fork HEAD:main
   ```

   This is a normal fast-forward push. If it is rejected, reconcile your fork's
   changes; do not force-push. This fork already contains the prepared configuration.
3. Open the fork's **Actions** tab and enable workflows. Repository policies must
   allow the pinned official `actions/checkout`, `actions/upload-artifact`, and
   `actions/download-artifact` actions.
4. The build workflow requests `contents: write` for the existing release-based
   ccache and optional draft release. It does not require `actions: write` or a
   separate personal access token. Other upstream maintenance workflows retain
   their own permissions and schedules; disable those schedules in your fork if
   you do not want its monitor/toolchain maintenance jobs.

## Run and download

1. Choose **Actions → Build and Release OnePlus Kernels → Run workflow**.
2. Select the branch containing these changes. Under `op_model`, choose:

   | Selection | Kernel builds |
   | --- | --- |
   | **OnePlus Ace 6T** (default) | `OP-ACE-6T`, A16 only |
   | **OnePlus 15R** | `OP15r`, A16 only |
   | **Both devices** | These two targets only |

3. Leave `make_release` off unless you want an additional **draft** release.
   Keep `mirror_toolchains` off: pinned tools are downloaded directly if the
   fork has no toolchain release cache. Set `clean_build` for an uncached build;
   `debug` additionally compiles common-tree modules and uploads diagnostics.
   The normal build compiles `Image`. Compiler optimization is O2. Leaving the
   timestamp blank uses build time; setting it fixes that part of build identity.
4. Open the run, inspect the matrix and per-device logs, then download its
   **Artifacts**. Successful builds upload an AnyKernel3 ZIP for each device.
   Artifacts expire after 90 days. Optional draft releases provide longer-lived
   downloads after you review and publish them yourself.

Example name:

```text
AK3_OP-ACE-6T_A16_android16-6.12.38_KSUN_33239_SuSFS_v2.2.0_K234f6e04_Sf37930f3_B<build-commit>.zip
```

Each ZIP includes `Image`, the pinned AnyKernel3 installer, `build-info.json`,
`manifest.xml`, and `kernel.config`. Full source revisions and the workflow
commit are in `build-info.json`; image/archive SHA256 values are in the job
summary. The workflow checks ARM64 Image format/size and ZIP integrity.

This is an installer archive that repacks the device's existing boot image,
not a prebuilt, device-signed `boot.img`. A raw `Image` is not a boot image and
must not be passed directly to `fastboot flash boot`. The template's version
check is enabled but does not check the regional model, exact firmware, module
CRCs, KMI generation, or security patch level.

## Firmware compatibility and stock recovery

Before installing, save these stock-system details:

```sh
adb shell getprop ro.product.model
adb shell getprop ro.build.fingerprint
adb shell getprop ro.build.version.incremental
adb shell getprop ro.build.version.security_patch
adb shell getprop ro.boot.slot_suffix
adb shell uname -a
adb shell getconf PAGESIZE
```

Match the actual device and regional firmware to the selected source branch.
Both pins report Android 16 / 6.12.38, KMI generation 5. Check the installed
kernel branch, full version, KMI generation, page size, vendor module ABI/CRCs,
and boot security metadata against the build. A matching version string alone
is insufficient; later OTAs can change private interfaces without changing the
kernel family. No exact OxygenOS/ColorOS firmware compatibility matrix has been
established here. The output retains WildKernels branding in its release string.
Android explains the role of the [kernel module interface and ABI checks](https://source.android.com/docs/core/architecture/kernel/abi-monitor).

The workflow retains the firmware's existing vendor modules, DTB and DTBO. It
does not rebuild or distribute the Qualcomm/OnePlus vendor drivers, vendor_dlkm,
system_dlkm, vendor_boot, or init_boot. The debug common modules are diagnostics,
not a vendor module replacement set. Establish that the installed firmware's
modules load against this kernel before treating it as usable. Android's
[boot partition documentation](https://source.android.com/docs/core/architecture/partitions/generic-boot)
describes why `boot`, `init_boot` and `vendor_boot` have different contents.

Before the first modification, obtain the exact unmodified boot image from the
installed firmware's full OTA/factory package, or make an off-device backup
while the stock system is still accessible. Keep separate images for each slot
if their installed firmware differs. If root already exists, an example for a
verified `boot_a` partition is:

```sh
adb exec-out su -c 'cat /dev/block/by-name/boot_a' > stock-boot_a.img
sha256sum stock-boot_a.img
```

Check the command succeeded and verify the image size/header; keep the backup,
checksum, firmware identifier and slot information on another machine. An
already modified boot partition is not an original stock backup. If root is
unavailable, retain the exact firmware image instead of attempting that command.
Keep original init_boot/vendor_boot images as well if another root method
previously modified them. AnyKernel3's temporary working copy is not a durable
stock backup.

Confirm bootloader access and a device-specific recovery procedure before
installation. To restore a confirmed matching stock image to **slot a's boot**,
an example in bootloader mode is:

```sh
fastboot getvar current-slot
fastboot flash boot_a stock-boot_a.img
fastboot reboot
```

Use that example only when slot a and its exact firmware/image match your
recorded state; use the corresponding partition/image for a different slot.
Do not overwrite the other slot or switch slots as a guessed recovery method.
Do not relock the bootloader with custom images installed. This workflow never
flashes or alters a connected device. Use a KernelSU-Next manager compatible
with commit `234f6e04` and SUSFS userspace/module compatible with v2.2.0;
compatibility with arbitrary current manager/module releases is unverified.

## Sources and investigation

The repository was inspected before changes at WildKernels commit
[`d137109ed3c84316ae562d679d42c548e2e090a6`](https://github.com/WildKernels/OnePlus_KernelSU_SUSFS/tree/d137109ed3c84316ae562d679d42c548e2e090a6).
The complete tree contains device JSONs under configs/a14–a16, local manifests,
four workflows, and composite actions for disk cleanup, source sync, building,
and release-backed cache restore/save. The other workflows monitor OnePlusOSS,
mirror toolchains and clean cached releases/runs. They do not compile kernels.

The release workflow previously defaulted to all Android generations, resolved
moving KernelSU/SUSFS branches, and downloaded an unverified custom ccache binary.
It now limits selection to these targets, reads a committed source lock and uses
the runner's distro ccache package. Both target JSONs alone opt into the minimal
profile. Other device JSONs/manifests remain intact.

Official manifests were compared at
[`OnePlusOSS/kernel_manifest@60e801f9aa07df0617ddb872141e5a1540d01cf8`](https://github.com/OnePlusOSS/kernel_manifest/tree/60e801f9aa07df0617ddb872141e5a1540d01cf8).
Their filenames are `oneplus_ace_6t.xml` and `oneplus_15r.xml`, not the local
`*_w.xml` names. Each official manifest has 33 projects; each WildKernels
manifest has seven. Meaningful differences:

- Both retain the official common-kernel and modules/device-tree sources.
  Their moving device branches are now replaced by explicit commits below.
- Official manifests also fetch `android_kernel_oneplus_sm8845` into
  `kernel_platform/soc-repo`, with WORKSPACE/build_with_bazel/device.bazelrc links.
  WildKernels omits this tree and the full vendor/Bazel build. Your existing
  source fork corresponds to this omitted SoC tree, not to `common`.
- WildKernels omits trusty, most Bazel rules/external tools, JDK, NDK, GCC
  sysroot, mkbootimg and other full-platform build dependencies. It retains the
  same pinned Clang, Rust, clang-tools and kernel-build-tools projects, and adds
  a pinned WildKernels AnyKernel3 template. This remains the existing direct
  common-kernel `make` build rather than a full official platform reproduction.
- `wild/sm8845` is a local-manifest selector, not an upstream Git branch. Archive
  sync resolves project remotes/revisions and downloads/extracts them on each run.

## Integration, optional features and remaining checks

The inspected KernelSU setup script can fall back after a failed checkout.
For these targets, the helper instead clones the official repository, checks
out the locked commit, verifies its history/version, and adds the same driver
symlink/Kconfig/Makefile integration without executing the downloaded script.
SUSFS supplies inline hooks; legacy manual hooks must not be applied again.
The [adaptation notes](../patches/sm8845/README.md) explain the complete checked
KernelSU patch and one common-kernel context adjustment. No runtime patch
failure is ignored. Required KSU, SUSFS and MODVERSIONS config values must
survive `olddefconfig` before compilation proceeds.

BBG, module blacklisting/interception/overlays, HMBIRD, general scheduler/memory/
I/O tuning, BBR/BBRv3, extra qdiscs, TTL, IP set/NAT additions, Unicode bypass,
Droidspaces, NTSync, fake config.gz, extra TMPFS flags and forced CPU tuning are
not required by this root integration and are disabled for these two targets.
O2 and source-default LTO are retained; extra inlining/config overrides are
skipped. Rust/binder and hardware-related stock config are retained. The
existing SUSFS-required protected-export cleanup remains. SELinux/CFI are not
explicitly disabled. Stock behavior still changes where root/SUSFS hooks act.
